# 学科课程化方案（Course Model）

> 目标：把每个学科从「工具箱」升级成「完整课程」——有教材依据、章节顺序、知识点、题目、思路讲解、学科介绍、应用与交叉。
> 参考样板：竞赛备战中心（总览 / 专题 / 练习 / 模拟 / 冲刺 / 知识卡）已被验证好用的结构。

---

## 一、现状盘点

| 维度 | 现在有 | 缺口 |
|---|---|---|
| 学科页 | 12 个（线代、微积分、概率…），每页 ~900 行、12 个功能 tab | 只有功能，没有章节与顺序 |
| 知识点 | 70 个考点（文章体：本质/什么时候用/步骤/例题） | 无章节归属、无前置关系、无教材对应 |
| 练习 | 29 个知识点生成器 | 与考点无映射（刚做了单向链接）、无难度梯度、无完整解答 |
| 思路 | 9 张解题流程图 | 未与具体题目绑定 |
| 学科介绍 | 无 | 完全空白 |
| 应用 / 交叉 | 无 | 完全空白 |
| 竞赛专区 | 22 个专题、8 个关卡、模拟卷、冲刺卡 | 这套结构可复用 |

**核心矛盾**：现在是「会算」，用户要的是「会学」。

---

## 二、课程模型：六件套

每门课由六部分组成，缺一不可：

1. **课程首页** — 一句话定位 / 先修要求 / 教材对照 / 章节树（带知识点数与掌握度） / 入门路径
2. **章节页** — 本章目标 / 核心定理清单 / 知识点列表 / 本章练习入口
3. **知识点页** — 复用现有考点文章，补「所属章节 / 前置知识 / 教材页码」
4. **练习集** — 每个知识点挂 3–5 题，分基础/进阶/竞赛，每题带思路提示 + 完整解答
5. **学科介绍** — 研究什么、核心对象、历史脉络、在数学体系中的位置（连 `/branches`）
6. **应用与交叉** — 应用领域（工程/物理/CS/金融）+ 与其他学科的交叉点

## 三、数据模型

```ts
// src/data/courses/linear-algebra.ts
export interface Course {
  id: string;
  title: string;
  tagline: string;              // 一句话定位
  textbook: { name: string; edition: string };
  prerequisites: string[];
  hours: number;                // 预计学时
  intro: { what: string; objects: string[]; history: string[] };
  chapters: Chapter[];
  applications: Application[];
  crossings: Crossing[];        // 与其他学科的交叉
}

export interface Chapter {
  id: string;
  title: string;
  textbookRef: string;          // 教材第几章
  goals: string[];
  lessonIds: string[];          // 指向 explainers.ts 里的考点 id
  exerciseTag: string;          // 指向练习库
}

export interface Application { title: string; scene: string; example: string }
export interface Crossing { subject: string; relation: string; courseId?: string }
```

**关键决策：lesson 复用现有 explainers，不新建内容体系。**
只给 `ExplainerTopic` 增加可选字段：

```ts
courseId?: string;   // 属于哪门课
chapter?: string;    // 属于哪一章
prereq?: string[];   // 前置考点 id
```

这样 70 个考点不需要重写，只是「挂」到章节树上。

## 四、页面与路由

| 路由 | 页面 | 说明 |
|---|---|---|
| `/course/:subject` | 课程首页 | 章节树 + 学科介绍 + 应用 + 交叉 |
| `/course/:subject/:chapter` | 章节页 | 目标 + 知识点列表 + 练习入口 |
| `/explainer?topic=xxx` | 知识点页（复用） | 增加面包屑「线代 / 第 1 章 行列式」 |
| `/practice?topic=xxx` | 练习（复用） | 增加「本章练习」批量入口 |
| `/linear-algebra` | 现有工具页（保留） | 从课程首页以「工具箱」形式进入，不删除 |

**不删除任何现有工具页**——它们是课程的「计算器」，是差异优势。

## 七、工作量与取舍

**完整做一门课** ≈ 6 章 × 5 知识点 = 30 个知识点 + 150 道题。
这比现有全部 70 个考点的体量还大——**不可能一次铺开**。

建议策略：**先「薄而完整」，再「逐个加厚」**

- 每章 3–5 个知识点（不是全部）
- 每个知识点 3 道题（基础/进阶/竞赛各一）
- 每门课 1 个应用 + 2 个交叉

这样一门课的「骨架」约 20 个知识点 + 60 题，一天能做一门；先让体验完整，再按用户反馈加厚。

**明确不做**：
- 不自动生成教材内容（质量不可控）
- 不追求覆盖所有学校教材（选主流版本）
- 不重写现有 70 个考点（挂载而非重建）

## 八、风险

| 风险 | 应对 |
|---|---|
| 内容量爆炸，做一半 | 骨架优先，每门课先跑通闭环 |
| 与现有工具页定位冲突 | 工具页保留为「计算器」，课程页负责「学习」 |
| 教材版权 | 只做章节对照与原创讲解，不复制教材原文 |
| 题目质量 | 每题必须过断言 + 我人工核一遍 |
